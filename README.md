# Мой год в форме

Личное веб-приложение (PWA) для iPad и iPhone: план питания на 30 дней, рецепты, закупки и готовка, тренировки с мини-степпером и одной разборной гирей, вес и фотопрогресс, ежемесячный разбор в ChatGPT. Открывается с иконки на экране «Домой», работает без интернета, данные хранятся только на устройстве.

Стартовый план — 02.11.2026–01.12.2026, перенесён дословно из «План_питания_2ноя_1дек_2026.xlsx» и «Рецепты_к_меню_ноябрь_2026.docx». Дальше приложение работает бессрочно: новые месяцы загружаются файлом `plan_update.json`.

## Что внутри

| Питание | 4 приёма пищи, связь «блюдо → рецепт» по таблице соответствий, «Нужно уточнить рецепт» вместо выдуманного, контейнеры на завтра |
| Рецепты | 28 рецептов из источника, порции 1–4 (пересчёт только структурированных количеств), пошаговый режим, хранение |
| Закупки и готовка | закупки 01.11 и 16.11 с отметками «Куплено», фактическими ценами, печатью и копированием; 9 готовок, включая сдвинутую 28.11 |

| Анализ с ChatGPT | ZIP-отчёт за месяц, запрос для ChatGPT, импорт `plan_update.json` с экраном «Было → Станет», откат, резервные копии |
| Настройки | расписание, цели, взвешивание и фото, перенос начала силовых, тема, удаление данных |

Релакс-день 29.11 — отдельная карточка без обязательных отметок и «штрафов». Калории и БЖУ не ведутся: ≈2450 ккал — только справочный ориентир.

## Команды

```bash
npm install         # зависимости
npm run dev         # разработка: http://localhost:5173 (service worker выключен)
npm run build       # сборка в dist/ — плоская папка, все пути относительные
npm test            # unit-тесты: даты, задачи, статистика, пересчёт рецептов, импорт, отчёт, резервные копии
npm run test:e2e    # сборка + 11 сценариев из ТЗ в Chromium (нужен: npx playwright install chromium)
npm run preview     # локальная проверка dist/ на http://localhost:4173
npm run typecheck   # проверка типов TypeScript
npm run figures     # картинка со всеми схемами упражнений → e2e/screens/figures.png
npm run icons       # иконки из tools/icon.svg
npm run seed -- План.xlsx Рецепты.docx   # пересобрать src/data/initial_seed.json из исходных файлов
```

Для проверки сценариев на конкретную дату откройте адрес с `?today=2026-11-02` (действует только в этой вкладке; `?today=off` — выключить).

## Публикация на GitHub Pages

**Вариант 1 — только с iPad, без сборки.** В архиве `god-v-forme-ipad-upload.zip` уже готовая сборка (10 файлов).

1. Распакуйте архив в «Файлах».
2. На github.com создайте публичный репозиторий, например `god-v-forme`.
3. «Add file → Upload files» → выберите **все файлы** из папки (не саму папку) → «Commit changes».
4. Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)` → Save.
5. Через 1–2 минуты появится адрес `https://<логин>.github.io/god-v-forme/`.

Обновление: загрузите все файлы нового архива поверх старых. Имена скриптов содержат хэш, старые файлы можно не удалять.

**Вариант 2 — исходный код и GitHub Actions.** Загрузите в репозиторий весь проект (с папками). В Settings → Pages → Source выберите «GitHub Actions». Каждый push в `main` запускает тесты, сборку и публикацию (`.github/workflows/deploy.yml`). Подпапка в адресе не важна: все пути в сборке относительные.

## Установка на iPad / iPhone

Откройте адрес в Safari → «Поделиться» → «На экран „Домой“» (если есть переключатель «Открывать как веб-приложение» — оставьте включённым) → «Добавить». Запускайте с иконки. Подробнее — `docs/USER_GUIDE.md`.

### Данные

- IndexedDB `god-v-forme`, схема версии 1 (`src/state/idb.ts`, `MIGRATIONS`). Новая версия схемы — новый шаг миграции; данные пользователя не сбрасываются.
- Seed загружается один раз при первом запуске (`meta.seedId`). Новый seed в обновлении приложения добавляет только отсутствующие дни и события.
- План (дни, версии шаблонов тренировок, закупки, готовка) и пользовательские записи (отметки, переносы, логи тренировок, вес, фото, чеки) хранятся раздельно. Импорт меняет только план и только начиная с `effective_from`; перед импортом сохраняется снимок для отката.
- Лог тренировки хранит копию шаблона на момент начала — история не зависит от последующих обновлений и откатов.
- Фото — Blob в IndexedDB, уменьшаются на устройстве (по умолчанию 1600 px), миниатюры отдельно.

### Отчёт для ChatGPT

`report_ГГГГ-ММ.zip`: `monthly_report.json` (схема 1.0.0, только введённые данные), `monthly_summary.md` (сводка на русском, запрос и схема `plan_update.json`), `manifest.json` (файлы, размеры, SHA-256), `photos/` — только выбранные вручную.

### Импорт plan_update.json

Схема и правила — в конце `monthly_summary.md` и в `examples/plan_update_example.json`. Типы изменений: `workout_template`, `calendar_training`, `meal_plan`, `meal_prep_event`, `shopping_event`, `goal`. Файл проверяется полностью; при ошибке показывается путь и причина, ничего не меняется. Строки с HTML, ссылками и `javascript:` отклоняются. Прошлые даты и дни с отметками не перезаписываются. Резкий рост нагрузки (+2 подхода, +50 % повторов, +4 кг) требует отдельного подтверждения; вес гири — не больше 24 кг.

### Резервная копия

ZIP с `backup.json`, фото и `manifest.json` (SHA-256 каждого файла). По желанию — шифрование паролем: PBKDF2-SHA256 + AES-GCM-256 (WebCrypto). После создания копия сразу читается обратно для проверки. Восстановление: «Заменить всё» или «Объединить» (остаётся более свежая запись).

## Отличия от предпочтительного стека в ТЗ

- **esbuild вместо Vite, свой service worker вместо vite-plugin-pwa.** В среде, где собиралось приложение, реестр npm был недоступен, а esbuild — тот же сборщик, что Vite использует внутри. Результат тот же: React + TypeScript, плоская статическая сборка, офлайн-кэш с версией по хэшу содержимого, баннер «Доступна новая версия».
- **Тонкая обёртка над IndexedDB вместо Dexie** (`src/state/idb.ts`, ~100 строк) — с транзакциями и версионными миграциями.
- Типы React локально проверялись упрощёнными объявлениями (`tsconfig.check.json`); полная проверка с `@types/react` идёт в GitHub Actions.

## Ограничения

- GitHub Pages — хостинг приложения, а не синхронизация. Данные iPad и iPhone не связаны: переносите их резервной копией через «Файлы».
- Офлайн работает после первой загрузки по https и кэширования.
- PWA — не приложение из App Store, но для этого сценария подходит. Очистка данных Safari или удаление иконки может стереть локальную базу — делайте резервные копии.
- Без фактических взвешиваний приложение не показывает динамику веса.
- Начало силовых можно перенести в настройках: до выбранной даты они помечаются «отложено» и не считаются пропусками.
- Проверка проведена в Chromium (unit + 11 сценариев e2e, офлайн, iPad и iPhone-размеры, тёмная тема). Перед ежедневным использованием проверьте установку и офлайн-запуск на своём iPad в Safari.
